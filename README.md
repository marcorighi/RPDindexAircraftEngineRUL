# RPDindex Aircraft-Engine Analyses — Two Distinct Workflows

This repository preserves **two scientifically different and independently
reproducible protocols**. Their data sources, endpoints, software entry points,
and release citations must not be interchanged.

Research contact: **Marco Righi**, Research Staff, Institute of Clinical Physiology
(IFC), National Research Council of Italy (CNR). Email: marco.righi@cnr.it;
ORCID: https://orcid.org/0000-0002-1448-0960.

| Protocol | Research goal | Input data | Entry point |
|---|---|---|---|
| **Historical v1.0.0 (August 2026)** | Remaining-useful-life (RUL) analysis, model validation, and separate test-set evaluation | Kaggle *Predictive Maintenance: Aircraft Engine* (`PM_train.csv`, `PM_test.csv`, `PM_truth.csv`) | `03_code/00_run_rpd_pipeline.sh` and the historical `03_code/50_...` through `85_...` programs |
| **IJPHM 2026 / released v2.0.0** | Retrospective discrimination of cycles within 30 cycles of a known end-of-life trajectory, nested alarm thresholds, and nine-model RPD component ablation | Original NASA C-MAPSS training trajectories **FD001, FD002, FD003, FD004** (709 engines) | `ijphm_2026/scripts/replay.sh` |

**IJPHM 2026 reproducibility:** Start with the dedicated
[`ijphm_2026/README.md`](ijphm_2026/README.md). That document explains how to
obtain the original NASA double ZIP, verify its SHA-256, reconstruct the four
local CSVs, install the recorded Python dependencies, run the 25 tests and
reproduce Stage 13/18 on one or all datasets. Its shortest execution sequence,
when run from inside `ijphm_2026/`, is:

```bash
bash scripts/setup_environment.sh
bash scripts/run_tests.sh
./.venv/bin/python scripts/prepare_nasa_data.py /path/to/NASA_turbofan_original.zip
bash scripts/replay.sh all both
```

This later study is **not prospective failure prediction** and does not include
independent nonfailure controls. The historical v1.0.0 repository DOI
`10.5281/zenodo.22012996` **does not identify** the new IJPHM 2026 source
code; the version-specific DOI of v2.0.0 is
`10.5281/zenodo.24038717`. Neither workflow redistributes NASA source data.

The material in the next sections (`02_raw_data/`, `03_code/`, the Kaggle
`download_data.py`, and `results_reference/`) documents the **historical v1.0.0
RUL protocol**. It remains available and unchanged.

## Historical v1.0.0 data

The input data are not redistributed. The analysis uses the Kaggle dataset
**Predictive Maintenance: Aircraft Engine** by Mohammed Hadani, dataset handle
`mhadani/predictive-maintenance-aircraft-engine`.

Required files:

```text
PM_train.csv
PM_test.csv
PM_truth.csv
```

From the repository root:

```bash
python3 -m pip install -r requirements.txt
python3 download_data.py
```

The downloaded files are checked against `DATA_SHA256.txt`, which records the
SHA-256 hashes of the exact files used for the reported analysis.

## Historical v1.0.0 analysis

`03_code/00_run_rpd_pipeline.sh` is the canonical entry point for construction
of the progressive RPD dataset.

Run the validated workflow from the repository root:

```bash
bash 03_code/00_run_rpd_pipeline.sh --clean

python3 03_code/50_analyze_train.py

python3 03_code/55_validate_train.py \
  --permutations 999 \
  --seed 20260812 \
  --jobs 14

python3 03_code/60_train_rul_model.py \
  --folds 5 \
  --seed 20260812 \
  --feature-sets rpd_global,raw_sensor,raw_plus_rpd \
  --models ridge,hgb \
  --horizons 20,50,100,150

python3 03_code/65_validate_rul_endpoints.py \
  --repeats 5000 \
  --seed 20260812 \
  --min-rul 20 \
  --max-rul 120

python3 03_code/70_predict_pm_test.py
python3 03_code/75_evaluate_pm_truth.py

python3 03_code/80_plot_rpd_local_global_example.py \
  --results-dir 04_results

python3 03_code/85_create_manuscript_figures.py \
  --tables 04_results/05_tables \
  --plot-data 04_results/02_plot_data \
  --figures 04_results/03_figures \
  --hires 04_results/04_figures_hires
```

The temporal-shuffle experiment is deterministic for the fixed base seed: its
per-engine/per-sensor random seeds are independent of process scheduling. The
`--jobs 14` value records the parallel configuration used for the reported run.
